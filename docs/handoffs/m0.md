## Entrega: orquestador · M0

**Hecho:**

- Stack de Expo SDK 58 instalado con `npx expo install` y base de compilación/pruebas configurada (`babel-preset-expo`, `jest-expo`, `tsconfig` con alias `@/`).
- Contrato fijado en `src/models/index.ts` (tipos `snake_case`) y `src/api/contracts/index.ts` (Zod).
- Rutas de M0 con el aviso permanente de la línea 123 y «Ajustes» con estado del servidor y de la sesión.
- Cliente HTTP: `Bearer`, timeout de 10 s, **un** refresh y **un** reintento ante `401`, tokens solo en `expo-secure-store`, `health` y endpoints de auth listos para M1.

**Archivos:**

- Configuración: `package.json`, `package-lock.json`, `babel.config.js`, `tsconfig.json`, `eslint.config.mjs`, `app.json`, `expo-env.d.ts`, `jest.setup*.cjs`, `jest.stubs/**`.

- Pruebas: `src/api/__tests__/**`, `src/controllers/__tests__/**`, `__tests__/**`, `ia/pruebas/m0-contrato.test.ts`.
- Docs: `docs/specs/m0-*.md`, `docs/adr/0006-*.md`, `docs/progreso.md`, `ia/bitacora-ia.md`.

**Cómo verificar:** `npm run check` → formato, lint, tipos y pruebas en verde, incluidas las 14 pruebas del guard de `ia/`.

**Decisiones:**

- SDK estable actual y una sola configuración de Jest (`jest-expo`), que también ejecuta las pruebas de `ia/` (ADR-0006).
- Refresh solo reactivo ante `401`; `expiraEnSeg` se guardará cuando lo use M14.
- SQLite se instala en M0 pero sus tablas llegan con M13.

**Pendiente / bloqueos:**

- Proveedor de token de EAS y APK: M17.
- El valor real de `expira_en_seg` al restaurar la sesión se fija en 0; si M14 lo necesita, `tokenStore` debe persistirlo (zona `api`).
- Probar en un dispositivo físico con `.env` válido (lo hace la persona).

**Dudas de la especificación:** el contrato no define respuesta de `/api/auth/refresh` con `usuario` ausente; se resuelve con un `GET /api/auth/yo` adicional, sin refresh.

**Revisión de seguridad:** primer informe **Rechazado** por evidencia de pruebas rota (suite de `tokenStore` no cargaba, URL leída al importar, matcher inexistente, sonda con `console.log`), `--passWithNoTests` y validación débil de hosts locales; código de producción correcto en secretos, tokens, red y privacidad. Tras corregir los 11 hallazgos, la re-revisión dio **Aprobado con observaciones**: se activó `no-console` en ESLint (nueva observación) y queda confirmar en un dispositivo físico el área táctil de «Ajustes». Evidencia: `npm run check` exit 0 con 115/115 pruebas y `ia/` 27/27.
